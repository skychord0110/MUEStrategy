# ui — コントロールパネル

リポジトリ直下の **`コントロールパネル.bat` をダブルクリック**すると開く設定画面。
ランナーの起動・停止、ストラテジーのON/OFF、監視銘柄の入れ替え、自動売買の安全スイッチ、
買付余力・建玉・評価損益の表示を1画面でまとめて行う。

```
MUEStrategy/
├─ コントロールパネル.bat      ← これをダブルクリック
├─ ショートカットを作る.bat    ← タスクバーに固定したいとき
├─ sounds/                     約定音（生成物）
└─ ui/
   ├─ control_panel.pyw        画面本体
   ├─ theme.py                 配色・フォント・共通ウィジェット
   ├─ config_io.py             config.yaml の真偽値だけを書き換える（コメント保持）
   ├─ symbols_update.py        最新CSV → symbols.yaml
   ├─ runner_control.py        ランナーの起動・停止と出力の取り込み
   ├─ make_sounds.py           約定音の生成
   ├─ sound_preview.py         約定音の試聴
   ├─ icon_candidates.py       アイコンの候補を描き出す（図柄の定義もここ）
   ├─ make_icon.py             選んだ案を control_panel.ico にする
   └─ make_shortcut.py         デスクトップにショートカットを作る
```

## タスクバーに固定する

**`.bat` は直接ピン留めできない**（Windowsの仕様）。ショートカット経由なら固定できる。

```powershell
.\ショートカットを作る.bat
```

デスクトップに「MUEStrategy コントロールパネル」ができるので、
右クリック →「タスクバーにピン留めする」（無ければ「その他のオプションを表示」の中）。
ピン留めの操作自体はプログラムから実行できないため、最後のクリックだけ手作業になる。

ショートカットは `.bat` を経由せず `pythonw.exe` を直接指すので黒い窓が出ない。

### アイコン

図柄は **B6「円相（赤銅／墨）」** — 切れ目のある環から線が外へ抜ける形で、
差し色は赤銅一色。16〜256pxの7サイズを1ファイルに収めてある。

図柄の定義は `icon_candidates.py` に一本化してある（`make_icon.py` はそれを呼ぶだけ）。
外部ライブラリを使わず、4倍で描いてから縮小することでアンチエイリアスをかけている。

```bat
python ui\make_icon.py                  いまの案(B6)で作り直す
python ui\icon_candidates.py            候補を ui\icon_preview\ に書き出して見比べる
python ui\icon_candidates.py --ico B3   別の案を選ぶ（そのあと CHOICE も直す）
```

差し替えたら `make_icon.py` の `CHOICE` を同じ記号にし、`make_icon.py` →
`ショートカットを作る.bat` の順に実行する。

#### ハマりどころが2つある

**1. 256px未満をPNGで入れてはいけない**

ICOの各画像はPNGでもDIB（非圧縮のBMP）でもよいことになっているが、
**Windowsが確実にPNGを解釈するのは256pxだけ**。それ未満をPNGで入れると
デコードされず、実測では32pxが色ノイズになった。
`icon_candidates.py` の `write_ico` は256pxだけPNG、それ未満をDIBで書く。
DIBには作法が3つあり、高さをANDマスクぶん2倍で申告する・画素を下の行から
並べる・色順をBGRAにする、のいずれを外しても化ける。

**2. Windowsはアイコンの絵をパス単位で覚えている**

同じファイル名のまま中身を差し替えても、古い絵が出続ける。
`ie4uinit.exe -show` は効かないことがあり（キャッシュDBの更新時刻が変わらない）、
`%LocalAppData%\Microsoft\Windows\Explorer\iconcache*.db` はExplorerが掴んでいるので
Explorerを止めないと消せない。

そこで `make_icon.py` は **案の記号を入れたファイル名**（`control_panel_b6.ico`）で
書き出し、`make_shortcut.py` はそれを指す。案を変えればパスも変わるので、
キャッシュに当たらず新しい絵がすぐ出る。名前固定の `control_panel.ico` にも同じ絵を
複製してあるが、これは古いショートカットが壊れないようにするためだけのもの。

すでにタスクバーに固定している場合は、**ピン留めを外して付け直す**
（固定側は別の .lnk なので、デスクトップ側を作り直しても入れ替わらない）。

### .bat は ASCII のみで書くこと

`cmd.exe` は `.bat` をOSのコードページ（日本語環境ではcp932）で読む。
UTF-8で日本語を書くと表示が化けるだけでなく、**行の解析が壊れて日本語の断片が
コマンドとして実行される**（実測: `'承繧ｯ繝ｪ繝・け' は認識されていません`）。
日本語のメッセージは Python 側から出すこと。

## 使う前に

1. **kabuステーションを起動してログインしておく**（APIを有効に）。
   起動していないと画面上部の「kabuステーション」が赤い「未接続」になる。
2. 環境変数を設定しておく（一度だけ。設定後はターミナルを開き直す）。

```bat
setx KABU_API_PASSWORD "本番用APIパスワード"
setx EDINET_API_KEY "取得したEDINET APIキー"
```

追加のインストールは不要（Tkinterは標準添付、yaml/requests はランナーと共通）。

## 画面の見かた

| 場所 | 内容 |
|---|---|
| kabuステーション | 緑「接続OK」＝APIが応答している / 赤「未接続」＝アプリ未起動かAPI無効 |
| ランナー | 緑「稼働中」＋経過時間。橙「稼働中（別プロセス）」＝このパネル以外から起動されている |
| 買付余力 | `/wallet/cash` の `AuKCStockAccountWallet`（三菱UFJ eスマート証券ぶん） |
| 評価損益 | 建玉の `ProfitLoss` の合計。プラスは緑地、マイナスは赤地 |
| 建玉 | 銘柄・株数・取得値・現在値・評価損益 |

**買付余力・建玉・評価損益はランナー稼働中しか出ない。** 停止中は「—」になるが異常ではない。

### なぜランナーが動いていないと口座情報が出ないのか

kabuステーションAPIのトークンは、公式リファレンス `POST /token` に
「**別のトークンが新たに発行された時**」に無効になると明記されている。
コントロールパネルが自分で `/token` を叩くと、稼働中ランナーのトークンがその瞬間に失効し、
参照系だけでなく**自動売買の発注・取消まで失敗**する。

そのためこのUIは**トークンを一切発行しない**。
ランナーが `strategies/runner/state/account.json` に15秒ごとに書き出した内容を読むだけ。
接続確認だけは、認証なしのリクエストを投げて応答が返るか（401でもよい）で判定している。

## 操作

### ランナー 起動 / 停止

画面下部の操作行にある。**緑の「▶ 起動」／赤枠の「■ 停止」が左**、
**赤い「緊急停止」が右端**。自動売買の赤枠の外に置いてあるのは、
起動・停止が自動売買だけでなく**ランナー全体の操作**だから。

手で打つ場合とまったく同じコマンドを実行する。

```bat
cd strategies\runner\src
python main.py --config ../config.yaml
```

停止は `state/stop.request` を置いてランナーに自分で後始末させる（通常3秒ほど）。
10秒で終わらなければ terminate、さらに5秒で kill する。

**このパネルを閉じるとランナーも止まる**（子プロセスとして動いているため）。
閉じる前に確認ダイアログが出る。パネルと独立に動かしたい場合はコマンドで起動すること。

### 銘柄更新

`extracted_stocks/` にある**最新の日付のCSV**の上から50件で `strategies/symbols.yaml` を作り直す。
50件なのはPUSH配信の銘柄登録上限がアプリ全体で50銘柄のため。
実行前に「追加◯件 / 除外◯件」を確認するダイアログが出る。
更新前のリストは `symbols.yaml.bak` に退避される。

コマンドから使うこともできる。

```bat
python ui\symbols_update.py --dry-run
```

### ストラテジーのON/OFF

チップの右側に**損切り/利確幅**が出る（`-1/+2%` = 損切り-1.0%・利確+2.0%）。
値は `config.yaml` から読んでいるので、設定を変えれば表示も追随する。

検知欄の **「投げ売り」は `-1/+2・-1.5/+3%`** と2つ並ぶ。この検知が
**決済幅の違う2つの仮想売買戦略の共通の入力**になっていることを示している。

| 欄 | チップ | 意味 |
|---|---|---|
| 検知 | 投げ売り `-1/+2・-1.5/+3%` | 板の観測。2つの戦略の共通の入力 |
| AI仮想売買 | 投げ売り反発 `-1/+2%` | 損切り-1.0% / 利確+2.0% |
| AI仮想売買 | 投げ売り反発 幅広 `-1.5/+3%` | 損切り-1.5% / 利確+3.0% |

**検知の「投げ売り」を押すと、2つの仮想売買戦略も一緒に切り替わる**（ONなら両方ON）。
片方だけ動かしたいときは、そのあとAI仮想売買欄で個別に外す。

チップを押すと `strategies/runner/config.yaml` の該当する `enabled:` だけが書き換わる。
**閾値の根拠や実績を書いたコメント（100行以上）は保持される**
（`yaml.safe_load` → `safe_dump` の往復ではコメントが全部消えるため、
該当行だけを差し替える方式にしている。詳細: `config_io.py`）。

### 自動売買（赤枠）

`strategies/autotrade/config.yaml` を書き換える。この枠の操作はすべて実弾に直結する。

**安全スイッチ**

- `enabled` を ON にするとき … 対象戦略と dry_run の状態を示した確認ダイアログが出る
- `dry_run` を OFF にするとき … **「実発注」と入力しないと切り替わらない**
- バッジ … 緑「停止中・安全」／橙「有効・DRY-RUN」／赤「★実発注★」

**実売買に使う戦略**

`strategies:` のチェックボックス。チェックした戦略だけが実際に発注する。
ONにするときは、いまの `enabled` / `dry_run` の状態から**何が起きるか**を示した確認が出る。

上の「AI仮想売買」と同じ名前が並ぶが**別物**。上は検知して仮想売買のログを出すかどうか、
こちらはそのシグナルで実際に発注するかどうか。実発注するには両方ONが必要。

自動売買が発注するのは**AI戦略のENTRYシグナルを受けたときだけ**なので、候補はAI戦略に限られる。
`config.yaml` にある `periodic_buy_rss` は現状効かないので出していない。
`投げ売り反発 幅広` も検証中のため仮想売買のみで、実売買の候補には入れていない
（実売買に昇格させるには `autotrade/config.yaml` の `strategies:` に
`panic_rebound_wide: false` を足し、UIの `AT_STRATEGIES` に1行加える）。

**資金上限**

`capital.max_use_amount`（このシステムが使ってよい上限）と
`capital.max_amount_per_symbol`（1銘柄あたりの上限）を入力して「保存」。
発注数量はここから決まる（上限 ÷ 株価 → 単元に切り捨て）。

- 全角数字・桁区切り・「円」付きでも受け付ける（`７０，０００円` → 70000）
- 1銘柄あたりの上限は使用上限額以下でなければ保存できない
- 未保存の入力があるあいだ、保存ボタンが橙の「保存 *」になる
- 保存前に「変更前 → 変更後」の確認ダイアログが出る

**緊急停止**は次の2つを行う。

1. `autotrade/config.yaml` の `enabled` を false にする
2. ランナーを停止する

**建玉は自動決済されない。** 保有中の建玉はkabuステーションから手動で決済すること
（ランナーを止めると損切り・利確・引け際の手仕舞いも動かなくなる）。

## 「変更が未反映です」の橙色の帯

ランナーは**設定と銘柄リストを起動時にしか読まない**。
稼働中に設定を変えると帯が出て、何を変えたかと再起動が必要なことを表示する。
変更したストラテジーのチップも橙になる。

帯の中の **「停止して再起動」** を押すと、次を自動で行う。

1. `state/stop.request` を置いてランナーの終了を待つ
2. 1秒待つ（銘柄登録の解除がkabuステーション側に届くのを待つため）
3. 同じコマンドで起動し直す

帯は、ランナー起動時点の設定と現在の設定を比べて出している。
このパネル以外（エディタなど）で設定ファイルを直接編集した場合も検出される。
ランナーが停止中は、次の起動時に自然に反映されるので帯は出ない。

## ログ

ランナーの標準出力をそのまま取り込んでいる（`logs/runner_YYYY-MM-DD.log` と同じ内容に加え、
想定外の例外トレースも拾える）。直近1500行を保持。
`INFO` 緑 / `WARN` 橙 / `ERROR` 赤。右上の「自動スクロール」で追従を切れる。

## 制限

- **このパネルから起動したランナーしか停止できない。** 別のターミナルから起動した
  ランナーは「稼働中（別プロセス）」と表示されるだけで、停止ボタンは効かない
  （その場合はそのターミナルで `Ctrl + C`、または `state/stop.request` を手で置く）
- **場中に再起動すると、それ以前に建てた建玉が自動売買の管理対象から外れる。**
  `AutoTrader` は建玉を自分のメモリ上でしか追っておらず、起動時に `/positions` から
  引き継がない。損切り・利確・引け際の手仕舞いがかからなくなるので、
  建玉があるときの停止・再起動には警告を出している（警告するだけで引き継ぎはしない）
- 資金管理のうち画面に出しているのは上限金額2つだけ。`max_positions` / `lot_size` /
  `min_free_margin` や損切り・利確の執行設定はファイルを直接編集する
- 画面の縦が足りないときは**全体が縦スクロール**する（収まっているときは
  スクロールバーを出さない）。内容の必要高さは約1,150pxで、1536x864の画面では
  ウィンドウが774pxしか取れず、そのままだと下端の操作行が見えなくなるため
- 角丸・グラデーションは使っていない（Tkinterのウィジェットでは描けないため、
  区切りはすべて1pxの罫線）。アイコンフォントも使わない（環境により豆腐になるため）
