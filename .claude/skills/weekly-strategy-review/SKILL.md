# 週次ストラテジーレビュー

毎週末に回す定例分析。**数字を出すのはスクリプト、意味を判断するのは自分**という分担で進める。

## 最初にやること

**日付は環境の現在日付を使う。ログの最終ファイル名から推測しない。**
2026-08-26に実施した回で、最新ログが `runner_2026-08-21.log` だったために
今日を08-21と誤り、出力先も「今週」の定義もずれた。週の切れ目を扱う分析で
日付を間違えると、結論そのものが1週ずれる。

```bash
python analysis/weekly_report.py --date <今日の日付>
```

これ1本で次が出る（出力先は `analysis/output/<日付>/`）。

| 出力 | 中身 |
|---|---|
| `trades_<日付>.csv` | 仮想売買の全トレード（ログから抽出） |
| `alerts_<日付>.csv` | 需給シグナルのアラート全件 |
| `bars_5m_<日付>.json` | 検証用の5分足（Yahoo Finance・口座には触れない） |
| `metrics_<日付>.md` | 週次/累計/戦略別/決済理由別/トリガー別、シグナル検証、銘柄の偏り |

株価は取得済みなら再利用する。取り直すなら `--refetch`、オフラインなら `--no-fetch`。

**週ごとに `parse_alerts_YYYY-MM-DD.py` のような使い捨てスクリプトを新規作成しない。**
以前はそれで28本の準重複が溜まった。条件を足したいときは `weekly_report.py` を
拡張する。過去の日付付きスクリプトは当時の記録として残してあるだけで、再利用しない。

## 次にやること（ここが本番）

`metrics_<日付>.md` は数字が並んでいるだけ。そこから
`analysis/output/<日付>/analysis_result_<日付>.md` を書く。これが成果物。

### 判断のチェックリスト

数字を鵜呑みにせず、必ず次を確認する。過去に実際これで結論が変わった。

- **銘柄の偏り**: `metrics` の「銘柄の偏り」表を見る。n=20でも8銘柄・上位3銘柄で
  76%なら、独立事例は実質3〜4件しかない。**件数ではなく独立性で判断する。**
- **接続断の日**: `WinError 10061` が多発した日はシグナルを取りこぼしている。
  2026-08-20は6,006件出ていた。該当日があればレポートに明記する。
- **サンプル数と有意性**: `*` は二項検定 p<0.05。付いていない差は「傾向」までに留める。
- **地合い**: 検証期間が上昇基調なら買い戦略は有利に出る。分離していないなら
  「地合いの寄与は分離していない」と書く。黙って伏せない。
- **約定可能性**: 仮想売買は指値が約定する前提。実弾ではそのぶん落ちる。

### レポートの構成

この並びで書く。過去回と揃えると週をまたいで比較できる。

```markdown
# 場中ログ分析 <日付>（week<N> ＋ 累計）
## 1. データと方法        対象ログ・件数・コスト仮定・有意性の判定方法・先読み排除の説明
## 2. 今週                戦略別の表（件数/勝率/平均/期待値/累計）
## 3. 累計                同じ表＋最大ドローダウン、決済理由の内訳、トリガー別
## 4. 独立検証            Yahoo 5分足でライブ実績を再現できるか
## 5. 提案                ①主力をどうするか ②止めるもの ③新しい候補
## 6. 限界と注意          接続断・期間の短さ・地合い・約定可能性・資格の但し書き
```

### 提案の書き方

- **変更しないことも提案**。代替案を全部試して現行が最良なら、そう書く。
  比較表を出して「試したがどれも劣った」と示すほうが、無理な改善案より価値がある。
- **止める提案も出す**。期待値が他より明確に低い戦略は、根拠と一緒に停止を勧める。
- **新戦略は必ず「仮想売買から」**。実弾を勧めるのは、別銘柄で20件以上たまり、
  複数週でプラスが続いてから。少数銘柄に偏ったサンプルで実弾を勧めない。

## 分析の作法

**先読みを入れない。** シグナルと同じ足の終値で約定させると、その足の中の
値動きを見てから買ったことになる。**次の足の始値**を使う。利確と損切りに
同じ足で両方触れたら、損切りが先に約定したとみなす（不利側に倒す）。

**重複排除は条件を適用したあと。** 「1銘柄1日1件」を先に全期間へかけると、
午前で枠を使った銘柄の午後シグナルが消える。実際これで午後の件数が
77件→25件に見え、結論を誤りかけた。`weekly_report.py` の `sub()` は
この順序になっている。

**往復コスト0.15%** を控除した「期待値」で語る。生の平均だけを出さない。

## 関連ファイル

| 場所 | 内容 |
|---|---|
| `analysis/output/<日付>/analysis_result_<日付>.md` | 過去回のレポート。前回の提案がその後どうなったかを必ず確認する |
| `strategies/AIStrategys/README.md` | 各戦略の根拠と数字。提案が採用されたらここも更新する |
| `strategies/runner/config.yaml` | 設定。採用時は根拠をコメントで併記する |
| `CLAUDE.md` | 分析結果の置き場所の規約 |

## 提案が採用されたら

仮想売買として実装する場合の流れ。詳細は `strategies/AIStrategys/README.md`。

1. `strategies/AIStrategys/src/detector.py` に戦略クラスを足す
2. `strategies/runner/src/main.py` で組み立てる（入力が板のPUSHでない検知は
   `RunnerEngine.submit_external()` 経由。建玉を触るスレッドを1つに保つため）
3. `strategies/runner/src/notifier.py` に表示名を足す
4. `strategies/runner/config.yaml` に設定と**根拠のコメント**を足す
5. `ui/control_panel.pyw` の `AI_STRATEGIES` にチップを足す
6. `tests/` に条件を固定するテストを書く（数字を後から安易に変えられないように）
7. **実売買の候補（`AT_STRATEGIES`）には入れない**
