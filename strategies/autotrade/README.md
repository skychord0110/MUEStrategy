# autotrade — 自動売買の設定と執行仕様

**⚠️ このディレクトリの設定で実際の資金が動きます。**
ステップ3で**実発注・取消を実装済み**。`dry_run: false` にすると本当に注文が出ます。

## 安全設計（三重の歯止め）

| # | 歯止め | 既定 | 意味 |
|---|---|---|---|
| 1 | `enabled` | **false** | false の間は発注APIを一切呼ばない |
| 2 | `strategies.*` | **すべて false** | true にした戦略だけが実売買の対象 |
| 3 | `dry_run` | **true** | 発注内容をログに出すだけで送信しない |

加えて `safety` の上限（1日の発注数・同一銘柄の回数・連射防止）が全経路に効く。

**実弾を動かす手順**: `dry_run: true` のまま数日運用してログの注文内容を確認 →
対象戦略だけ `strategies.<名前>: true` → `enabled: true` → 最後に `dry_run: false`。
一度に全部切り替えないこと。

## 資金管理

- 口座区分は **現物（cash）**。買いから入る戦略のみのため
  （将来「売りから入る」戦略を作る場合、その戦略だけ信用＝margin にする）
- `max_use_amount`（既定30万円）を上限に、残高を参照して発注数量を決める
- 数量 = `上限金額 ÷ 株価` を **単元（100株）の倍数に切り捨て**

| 株価 | 発注数量 | 約定金額 |
|---|---|---|
| 515円 | 500株 | 257,500円 |
| 700円 | 400株 | 280,000円 |
| 1,490円 | 200株 | 298,000円 |
| 2,448円 | 100株 | 244,800円 |

## 執行仕様

### エントリー（新規買い）

シグナル発生時に成行で新規建て。`max_positions`・`max_entries_per_symbol_per_day` で
建玉数と回数を制限する。

### 利益確定 — 建玉と同時に注文を出さない

**他者のアルゴに手の内を読まれるのを避けるため**、建玉と同時には決済注文を出さない。
売り気配（Ask）が **目標価格の2ティック以内**に接近した時点で、目標価格に指値を出す。

### 損切り — トリガー発動後の執行手順

トリガー価格 = `エントリー価格 × (1 − stop_loss_pct/100)`。
現在値がここに達したら発動し、**その時点の買い気配の位置**で execution が分岐する。

```
                      トリガー価格
                          │
   (A) 買い気配がここ ────┤ 1ティック以内
                          │  → 買い気配に指値をぶつける（即約定狙い）
                          │     間に合わず気配が下がったら同条件で指し直す
                          │
   (B) 買い気配がここ ────┤ 1ティックより下
                          │  → 仲値に売り指値
                          │     10秒ごとに1ティックずつ下げて指し直し
                          ▼
   追いかけ下限 ──────────  エントリー価格 −3%
                             （これ以上は下げず、同価格で指し直し続ける）
```

- 仲値 = (買い気配 + 売り気配) ÷ 2。呼値に乗らない場合は**不利側（切り下げ）**に丸める
- `max_chase_pct_from_entry: 3.0` が追いかけの下限。到達後は同価格で粘り、
  それでも約定しなければ下記の強制手仕舞いに引き継がれる

### 引け際の強制手仕舞い

`15:25` までに決済が約定しなければ、`15:26` に **買い気配 −3%** の売り指値を出す
（呼値の刻みに切り下げ）。

**ティック数ではなく率で指定する理由**: 同じ「10ティック」でも実質の深さが銘柄で
まるで違い、「確実に手仕舞う」という目的に反するため。

| 銘柄 | 株価 | 10ティック下 | −3%指定 |
|---|---|---|---|
| ステラファーマ | 318円 | 308円（**−3.14%**） | 308円（−3.14%） |
| アサカ理研 | 2,740円 | 2,730円（**−0.36%**） | 2,657円（−3.03%） |
| クオリプス | 5,400円 | 5,300円（−1.85%） | 5,230円（−3.15%） |

10ティック指定では深さが **0.36%〜3.14%（8.6倍のばらつき）** になり、浅い銘柄では
板寄せで約定しない恐れがあった。率指定なら **3.00%〜3.23%（1.08倍）** に揃う。
呼値への丸めは常に切り下げ（＝深い側・約定しやすい側）なので、必ず−3.00%以上深くなる。

東証は **15:25〜15:30 がクロージング・オークション（板寄せ）**のため、この時間に出した
指値は即時約定せず、大引けの単一価格で約定する。したがってこの注文は
**「価格下限付きの引成」**として機能する（−3%まで貫いていても、実際の約定は
大引け価格になるため不当に不利な価格では約定しない）。

## 残っているリスク（認識しておくこと）

- **損切りはプログラム監視方式**。runnerのログには `WebSocket切断` が22回記録されている。
  切断中・PCスリープ中・アプリ再起動中は損切りが執行されない。
  `max_chase_pct_from_entry` は「追いかける価格の下限」であって、
  **プログラムが停止した場合の保護にはならない**
- 追いかけ下限（−3%）に達しても約定しない状況（ストップ安・特別気配）では、
  15:26の強制手仕舞いも約定しない可能性がある
- 検証で使った価格はPUSHの現在値であり、**実際に売れる価格（板の厚さ次第）とは異なる**

### ステップ1で実装したもの

```
src/
├── tick_size.py      呼値の判定・率/ティック移動（純ロジック・API非依存）
├── sizing.py         発注数量の計算（純ロジック・API非依存）
├── account.py        余力・建玉・銘柄情報の取得とログ出力（参照系APIのみ）
├── order_builder.py  /sendorder のリクエスト組み立て（純ロジック）※ステップ2
```

計算ロジックはAPI非依存の純関数として分離してあり、kabuステーションが無くても
単体テストできる。`account.py` は参照系（GET）のみを呼び、**発注APIは呼ばない**。

**動作確認:**

```powershell
cd strategies\autotrade\src
python account.py --config ../config.yaml
# 特定銘柄だけ見る場合
python account.py --config ../config.yaml --symbols 4889,6433
# 銘柄を入れ替えた直後（未登録銘柄が400になる場合）
python account.py --config ../config.yaml --register
```

**⚠️ 未登録銘柄は `/symbol`・`/board` が 400 を返す**

kabuステーションに**銘柄登録されていない銘柄**は、銘柄情報も板情報も取得できない
（2026-08-10に確認: symbols.yaml を入れ替えた直後、新規追加した9銘柄だけが
`400 Bad Request` になった）。

- 統合ランナーを起動すれば起動時に登録されるので、通常はそちらを先に動かせばよい
- 単体で確認したい場合は `--register` を付ける（**全解除→登録**を行う）
- `--register` は kabuステーション全体の登録を書き換えるため、
  **統合ランナーの稼働中には使わないこと**（PUSH配信が切り替わる）

### ステップ2で実装したもの

`order_builder.py` は公式仕様(v1.5)の `RequestSendOrder` に沿って注文を組み立てる。
**注文パスワードは不要**（`/token` のトークンで認証する）。現物は売買で必須値が変わる:

| | DelivType | FundType |
|---|---|---|
| 現物**買** | 2（お預り金） | `"02"`（保護） |
| 現物**売** | 0（指定なし） | `"  "`（半角スペース2つ） |

`executor.py` は上記の四重の歯止めを通したうえで、dry_run なら次のように出力する:

```
[DRY-RUN 発注] 4889 買 200株 成行 — [エントリー(成行買い)]
          送信予定のボディ: {'Symbol': '4889', 'Exchange': 1, ...}
```

`capital.account_type`（2=一般 / 4=特定 / 12=法人）は**自分の口座に合わせること**。

### ステップ3で実装したもの

`kabu_client.py` に発注系を追加（`send_order` / `cancel_order` / `get_orders`）し、
`executor.py` から使う。**注文パスワードは不要**（トークン認証）。

| 機能 | メソッド | 挙動 |
|---|---|---|
| 発注 | `place()` | 安全弁を通過し `dry_run: false` なら `/sendorder`。`Result=0` で受付、OrderIdを保持 |
| 取消 | `cancel()` | `/cancelorder`（必須は `OrderId` のみ）。損切りの指し直しで使う |
| 一括取消 | `cancel_all()` | 未約定を全て取消（緊急停止・引け際の切り替え用） |
| 状態確認 | `refresh_orders()` | `/orders` で `State` を見て、終了(5)なら未約定リストから外す |

注文状態（`State`）: 1=待機 / 2=処理中 / 3=処理済 / 4=訂正取消送信中 /
**5=終了**（発注エラー・取消済・全約定・失効・期限切れ）

**エラー時の挙動**（テスト済み）:
- `Result≠0`（発注エラー）→ 未約定として管理しない。ログにエラーコードを残す
- 通信エラー → 例外を握って `{"error": ...}` を返す。**プロセスは落ちない**
- クライアント未設定で `dry_run: false` → 発注せず error を返す

### ステップ4で実装したもの

`position_manager.py` — 建玉1件の執行を管理する状態機械。**API非依存の純ロジック**で、
`on_tick(板情報, 時刻)` が「実行すべきアクションのリスト」を返すだけ。自分では発注しない
（**状態機械が判断し、Executorが実行する**分担）。これにより全経路をテストできる。

```
HOLDING ──(売り気配が目標の2ティック以内)──→ TP_PLACED
   │                                            │
   │←────────(利確を取消して損切りへ)───────────┤
   │                                            │
   ├──(現在値が損切りトリガーに到達)──→ STOP_CHASING
   │                                     （気配を追いかけて指し直し）
   │                                            │
   └──(15:26 到達)──→ CLOSING_OUT ←─────────────┘
```

**優先順位**: 引け手仕舞い > 損切り > 利確。既に利確を出していても、損切りが発動すれば
**取消してから**損切りを出す（同時に複数の売り注文を出さない）。

検証済みの挙動（エントリー1000円・TP+2%・SL−2%・下限−3%の例）:

| 場面 | 動作 |
|---|---|
| 売り気配1017 | まだ何もしない（閾値は1018＝目標1020の2ティック下） |
| 売り気配1018 | 目標1020に指値を開示 |
| 現在値980到達・気配980 | 損切りA: 買い気配980にぶつける |
| 気配が978へ | 取消して978に指し直し |
| 気配が960へ | **下限970で止まる**（それ以下は追わない） |
| 気配が離れて発動 | 損切りB: 仲値977に指値 → 10秒後976 → 20秒後975 |
| 15:26到達 | 取消して 買い気配−3% に指値（**下限は適用しない**＝確実性優先） |

引け手仕舞いだけ下限（−3%）を適用しないのは、目的が「確実に手仕舞う」ことだから。

### ステップ5: 統合ランナーへの組み込み

`trader.py`（AutoTrader）が全体を繋ぐ。統合ランナーを起動すれば自動売買も一緒に動く:

```powershell
cd strategies\runner\src
unner\src
unner\src
python main.py --config ../config.yaml
```

**動作の流れ**

1. AIストラテジーが ENTRY シグナルを出す（仮想売買は従来どおり並行して継続）
2. `AutoTrader.on_signal()` が余力を取り直し、数量を計算して成行買いを発注
3. 以降のPUSHごとに `PositionManager.on_tick()` が判断し、`Executor` が発注・取消
4. `poll()` が注文の約定・終了を確認して状態を進める

**役割分担**（テストしやすさのため厳密に分けてある）

| 担当 | 責務 |
|---|---|
| AIStrategys | いつ入るか（シグナル） |
| sizing / account | いくら買えるか |
| PositionManager | どう決済するか（**判断のみ・発注しない**） |
| Executor | 実際に発注・取消する（安全弁つき） |
| AutoTrader | 上記を繋ぐ |

**dry_run では擬似約定でログを追える**。実際には発注しないため注文番号が返らないので、
擬似的な番号を振り「指値に相場が届いたら約定した」とみなして状態を進める。
これにより **実弾を動かさずに1日の流れをログで検証できる**。

**エラー時**: 自動売買で例外が出ても握りつぶしてログに残し、
PUSH処理・検知・仮想売買は止まらない（ランナー全体は継続する）。

### 呼値（tick_size.py）について

執行ロジックの「2ティック以内」「1ティック下」「10ティック貫く」はすべて呼値の単位に
依存する。単位は銘柄の `PriceRangeGroup` と価格水準で決まり、**固定値にはできない**:

| 呼値グループ | 例 |
|---|---|
| 10000（通常銘柄） | 3000円以下→1円 / 5000円以下→5円 / 30000円以下→10円 |
| 10003（TOPIX500構成） | **1000円以下→0.1円** / 3000円以下→0.5円 / 10000円以下→1円 |
| 10004（売買単位1口のETF等） | 10000円以下→1円 / 30000円以下→5円 |

同じ800円の銘柄でも、通常銘柄なら1円刻み、TOPIX500構成なら**0.1円刻み**と10倍違う。
`shift_ticks()` は刻みが変わる水準をまたぐ場合も1ティックずつ引き直して計算する
（例: 3005円の3ティック下 = 3005→3000→2999→**2998円**）。

未知の呼値グループは既定値で誤魔化さず例外を投げる（価格がずれるため）。

### 数量計算（sizing.py）について

```
使用可能額 = min(max_use_amount, max_amount_per_symbol, 買付余力)
数量      = 使用可能額 ÷ 現在値 → 売買単位(TradingUnit)の倍数に切り捨て
```

買付余力は `GET /wallet/cash` の **`AuKCStockAccountWallet`**（うち三菱UFJ eスマート証券
可能額）を使う。`StockAccountWallet`（合計）ではない。

見送りになる条件: 余力が `min_free_margin` 未満 / 建玉が `max_positions` に到達 /
1単元も買えない / 現在値または余力が取得できていない。
