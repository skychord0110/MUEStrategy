# AIStrategys — ログ分析に基づくAI提案ストラテジー（仮想売買）

2026-07-13〜07-17のrunnerログ分析（[../../analysis/](../../analysis/README.md)）から
導いた買い戦略を、**発注なしの仮想売買（ペーパートレード）**として実装したもの。
統合ランナー（strategies/runner）に組み込まれており、`runner/src/main.py` を
実行すれば他のストラテジーと同様に検知・仮想売買の結果が `runner/logs/` に記録される。

## 収録ストラテジー

### 1. afternoon_reversal — 午後の下値大口買い検知・引け戻り

- **エントリー**: 13:00〜15:00にUNDER急増アラートが点灯し、**現在値が500円以上**の銘柄を、
  その時点の現在値で仮想買い（同一銘柄は1日1回まで）
- **決済**: 損切り-2% / 利確+2%、どちらにも達しなければ大引け（15:30）
- **根拠（2026-07-13〜17の初期検証）**: 23トレード・勝率69.6%・期待値+0.63%/回
  （スリッページ1ティック控除後）。前場のシグナルは期待値-1%のため使わない
- **価格下限フィルタ（min_entry_price=500）の追加根拠（2026-07-13〜24の両週検証）**:
  500円未満の低位株は勝率50%とノイズが大きく、500円以上に絞ると勝率71%→81%・
  期待値+0.79%/回に改善（両週ともプラスで頑健）。`analysis/analysis_result_2026-07-24.md` 参照。
  `min_entry_price: 0` にすればフィルタ無効（旧挙動）
- **今週(07-21〜24)の実稼働フォワード実績（フィルタ導入前）**: 12トレード・勝率63.6%・
  期待値+0.115%/回。バックテストより劣化しており、フィルタ版も実運用では下振れる前提で見ること

### 2. confluence — 複合シグナル

- **エントリー**: 13:00〜15:00に、30分以内で「**UNDER急増**」と「**小口売り連続**」の
  **両方**が同一銘柄に点灯したら、その時点の価格で仮想買い（同一銘柄は1日1回まで）。
  分析で有効だったのはこの2種の組み合わせのため、投げ売り検知は判定に使わない
- **決済**: 損切り-1% / 利確+1%、どちらにも達しなければ大引け
- **根拠（同上）**: 勝率80%・期待値+0.65%/回。**ただしn=5と極小サンプル**のため、
  まずはこの仮想売買ログでフォワード検証する位置づけ

### 3. panic_rebound — 投げ売り反発（セリングクライマックス）

- **エントリー**: 投げ売り検知（`stage: DUMP` ＝ 安値圏でOVER急減し、ほぼ同数が買い気配に
  ぶつけられた＝投げが出切った局面）で仮想買い（同一銘柄は1日1回まで）
- **決済**: 損切り-1% / 利確+2%（リスクリワード1:2）、未達は大引け
- **他2戦略との違い**: **終日が対象**（午後限定でない）。投げ売りは寄り付き直後の
  パニックでも起こり、検証でも前場・後場の双方でプラスだったため時間帯を絞っていない。
  価格フィルタも既定では無効（低位株でも機能したため）
- **根拠（2026-07-13〜31・銘柄1日1回・コスト1ティック控除後）**:
  SL-1%/TP+2% で **n=12・勝率66.7%・期待値+0.678%・PF2.72**
  （SL-1%/TP+1%なら勝率75.0%だが期待値+0.263%と低い）
- **⚠️ サンプルが極小で有効性は未確定**: n=12しかなく、**week1は勝率40%・期待値-0.43%と
  マイナス**。プラスはすべてweek3由来。この戦略は「有望だから採用」ではなく
  「フォワード検証してから判断する」段階にある

### 4. afternoon_reversal_ranked — 午後引け戻り・順位優先版

**1と検知条件も決済ルールもまったく同じで、エントリーの取捨選択だけが違う。**

| 銘柄リストの順位 | 動き |
|---|---|
| 上位 `top_rank` 位以内（既定25位） | 従来どおり即エントリー |
| それより下 | `late_entry_after`（既定14:00）以降でないとエントリーしない |

順位は [`../symbols.yaml`](../symbols.yaml) の並び順、つまり `extracted_stocks/*_export.csv`
のR/Rスコア順。ランナーが起動時に `set_ranks()` で渡す。
順位が分からない銘柄は下位として扱う（安全側）。

- **根拠（2026-08-14の5週間分析）**: 午後UNDER急増を順位で分けると、
  **決済ルールを5つ変えても上位が下位を上回った**

  | 順位 | SL2/TP2 | 大引け | 60分後 |
  |---|---|---|---|
  | 1〜25位 (n=32) | 90.6% / +0.897% | 84.4% / +0.574% | 75.0% / +0.684% |
  | 26〜50位 (n=44) | 65.9% / +0.464% | 65.9% / +0.481% | 63.6% / +0.442% |

- **なぜ「上位だけ」にしないのか**: 上位25位に絞ると取引機会が21日→16日に減り、
  累計リターンがむしろ落ちた（+13.29% → +11.42%）。下位も遅い時間帯なら拾うことで
  機会を残す。1日1建玉で回した実測（21営業日・コスト0.15%控除後）:

  | 運用 | 取引 | 勝率 | 1回あたり | 累計 | 負け（最悪） |
  |---|---|---|---|---|---|
  | 上位50・その日最初（＝戦略1） | 21 | 76.2% | +0.633% | +13.29% | 3回（−2.00%） |
  | 上位25のみ | 16 | 93.8% | +0.714% | +11.42% | 1回（−1.18%） |
  | **本戦略** | **18** | **94.4%** | **+0.708%** | **+12.74%** | **1回（−1.18%）** |

  累計は戦略1とほぼ同じまま、**負けを3回→1回、最悪値を−2.00%→−1.18%** に減らせる。
- **需給の読み**: R/Rスコア上位は「大幅下落後に空売り機関が買い戻しに入っている」銘柄。
  売り手が枯れかけたところに下値の大口買いが重なると反発しやすい。
  実際、上位25位は**75%が買い戻しあり**、26位以下は**18%**だった
- **⚠️ 上位25位の標本は n=32 と少なく、week2は2件でマイナス**
- 詳細: [../../analysis/analysis_result_2026-08-14.md](../../analysis/analysis_result_2026-08-14.md) の追補

クラスは `AfternoonReversalStrategy` を継承し、`on_signal` の入口に順位の関門を足しただけ。
戦略1と同時に有効にすると、**上位25位の銘柄では両方が同時にエントリーする**
（下位銘柄の13時台は戦略1のみ）ので、順位フィルタの効果をログで直接比較できる。

### 5. panic_rebound_wide — 投げ売り反発・幅広版

**3と検知はまったく同じで、損切り・利確の幅だけが違う。** どちらの決済幅が実際に効くかを
**並走させて比べる**ための戦略。既存の `panic_rebound` は変更していない。

- **決済**: 損切り-1.5% / 利確+3.0%（リスクリワード1:2）、未達は大引け
- **根拠（2026-08-14の5週間分析・同一銘柄1日1回に整理した n=20・コスト0.15%控除後）**:

  | 決済ルール | 勝率 | 期待値 | コスト後 |
  |---|---|---|---|
  | SL-1.0% / TP+1.0% | 80.0% | +0.594% | +0.444% |
  | **SL-1.5% / TP+3.0%（本戦略）** | **70.0%** | **+1.242%** | **+1.092%** |
  | SL-2.0% / TP+2.0% | 75.0% | +0.826% | +0.676% |

  **最大益の中央値が+2.02%あるのに対し、最大損の中央値は-0.87%。**
  伸びる余地に対して利確が早く、損切りが浅すぎるという読み。
  勝率は落ちるが期待値は倍になる。
- **週別（SL1.5/TP3.0）**: week1 -0.54%(5) / week3 +1.91%(7) / week4 +1.36%(6) / week5 +3.00%(2)
- **⚠️ n=20と少なく、week1はマイナス。** 実発注の対象にはしていない（仮想売買のみ）
- 詳細: [../../analysis/analysis_result_2026-08-14.md](../../analysis/analysis_result_2026-08-14.md)

クラスは `PanicReboundStrategy` を使い回している（判定ロジックが完全に同一で、
違いは設定値だけのため）。`PaperBook` はインスタンスごとに独立しているので、
2つの仮想建玉が混ざることはない。同じ投げ売りシグナルで**両方が同時にエントリーする**。

### 6. accumulation_follow — 買い集め追随

**この戦略だけ、他の5つと性質が2つ違う。**

1. **利確を置かない**（損切りに触れなければ大引けまで持ち切る）
2. **入力が板のPUSHではない**。歩み値をポーリングする
   `periodic_buy_zscore`（定期買い集め検知）から来る

- **エントリー**: 定期買い集め検知の **STRONG** が点灯した銘柄。既定は
  **午前（09:00〜11:00）のみ**、500円以上、同一銘柄は1日1回
- **決済**: 損切り **-2.0%** のみ。触れなければ大引け
- **根拠（2026-08-21の分析・07-21〜08-21のアラートをYahoo Financeの5分足で検証）**:

  | 決済ルール | 件数 | 勝率 | 期待値 |
  |---|---:|---:|---:|
  | **大引けまで持ち切り（本戦略）** | 20 | **65.0%** | **+0.56%** |
  | 損切り-2%のみ | 20 | 60.0% | +0.40% |
  | 利確+2% / 損切り-2% | 20 | 60.0% | +0.25% |

  **利確を置くと期待値がほぼ半減する。** 買い集めは1日かけて進むため、
  +2%で切ると伸びしろを捨てることになる、という解釈と整合する。
  時間帯は午前(09-11時)が n=14 期待値+0.52%、午後は n=4 期待値-0.19% で不発。
  WATCHは期待値-0.38%のため入力に含めない。

- **⚠️ 実発注に使ってはいけない。** 上記20件は**わずか8銘柄**から出ており、
  うち16件が3銘柄（4013・6580・4414）に集中している。検出日も8日のみ。
  **実質3〜4の独立事例しかなく、統計として成立していない。**
  別銘柄で20件以上たまるまでは仮想売買のまま様子を見ること。
- 詳細: [../../analysis/output/2026-08-21/analysis_result_2026-08-21.md](../../analysis/output/2026-08-21/analysis_result_2026-08-21.md)

**入力の受け渡し**: 定期買い集め検知は別スレッドで動くため、そのまま
仮想建玉を触らせるとPUSHスレッドと競合する。検知側は
`RunnerEngine.submit_external()` にアラートを積むだけにして、
実際の配布は `handle()`（PUSHスレッド）が行う。歩み値ベースの検知は
価格を持たないので、ランナーが直近のPUSHで観測した現在値を補ってから渡す
（一度もPUSHが来ていない銘柄は価格不明としてエントリーを見送る）。

## ログの見方

```
[AI午後引け戻り/エントリー] 4165 4165: UNDER急増を検知、560.0円で仮想買い（損切り-2.0%/利確+2.0%/残りは大引け・発注なし）
[AI午後引け戻り/決済:利確] 4165 4165: 仮想決済 560.0円→571.5円 (+2.05%)
[AI複合シグナル/エントリー] 6620 6620: small_lot_sell_detector+under_surge_detector が30分以内に点灯、735.0円で仮想買い（…）
[AI複合シグナル/決済:大引け] 6620 6620: 仮想決済 735.0円→741.0円 (+0.82%)
[AI投げ売り反発/エントリー] 4813 4813: 投げ売り を検知、338.0円で仮想買い（損切り-1.0%/利確+2.0%/残りは大引け・発注なし）
[AI投げ売り反発/決済:利確] 4813 4813: 仮想決済 338.0円→345.0円 (+2.07%)
[AI投げ売り反発(幅広)/エントリー] 4813 4813: 投げ売り を検知、338.0円で仮想買い（損切り-1.5%/利確+3.0%/残りは大引け・発注なし）
[AI投げ売り反発(幅広)/決済:利確] 4813 4813: 仮想決済 338.0円→348.5円 (+3.11%)
```

`AI投げ売り反発` と `AI投げ売り反発(幅広)` は**同じ投げ売りで同時にエントリーする**。
片方だけ利確・損切りになるので、決済幅の優劣をログだけで比較できる。

決済理由は `利確` / `損切り` / `大引け` / `大引け(補完)` の4種。
「大引け(補完)」は当日中に大引けのPUSHが受信できなかった銘柄を、
翌営業日の最初のメッセージ時に当日最後の観測値で決済扱いにしたもの。

週次の勝率・期待値の集計は、ログの `決済:` 行の `return_pct` を集めれば算出できる
（analysis/ のスクリプトと同じ要領）。

## 設定（runner/config.yaml の strategies セクション）

```yaml
  afternoon_reversal:
    enabled: true
    entry_start: "13:00"   # 仮想エントリーを許可する開始時刻
    entry_end: "15:00"     # これ以降は新規エントリーしない
    stop_loss_pct: 2.0
    take_profit_pct: 2.0
    min_entry_price: 500.0 # この価格未満の銘柄はエントリーしない（0で無効）

  panic_rebound:
    enabled: true
    entry_start: "09:00"   # 終日が対象（午後限定でない）
    entry_end: "15:00"
    stop_loss_pct: 1.0
    take_profit_pct: 2.0
    min_entry_price: 0.0   # 価格下限（0=無効）
    stages: ["DUMP"]       # DUMP=買い気配へぶつけ / ABSORBED=投げ売り吸収

  afternoon_reversal_ranked:   # 検知・決済は afternoon_reversal と同じ
    enabled: true
    entry_start: "13:00"
    entry_end: "15:00"
    stop_loss_pct: 2.0
    take_profit_pct: 2.0
    min_entry_price: 500.0
    top_rank: 25               # この順位までは即エントリー
    late_entry_after: "14:00"  # それ以下の順位はこの時刻以降のみ

  panic_rebound_wide:      # 検知は panic_rebound と同じ。決済幅だけが違う
    enabled: true
    entry_start: "09:00"
    entry_end: "15:00"
    stop_loss_pct: 1.5
    take_profit_pct: 3.0
    min_entry_price: 0.0
    stages: ["DUMP"]

  confluence:
    enabled: true
    window_seconds: 1800   # UNDER急増と小口売り連続がこの秒数以内に両方揃ったら発火
    entry_start: "13:00"
    entry_end: "15:00"
    stop_loss_pct: 1.0
    take_profit_pct: 1.0
```

コントロールパネル（`ui/`）の「AI仮想売買（発注なし）」からもON/OFFできる。

各AIストラテジーは基礎ストラテジーのアラートを入力にするため、**上流がOFFだと発火しない**。

| AIストラテジー | 必要な基礎ストラテジー |
|---|---|
| afternoon_reversal / afternoon_reversal_ranked | under_surge_detector |
| confluence | under_surge_detector ＋ small_lot_sell_detector（両方） |
| panic_rebound / panic_rebound_wide | panic_sell_detector |
| accumulation_follow | periodic_buy_zscore（`strategies` ではなくトップレベルの設定） |

`afternoon_reversal_ranked` は銘柄リストの順位も使うため、
**`symbols.yaml` の並び順が変わると挙動が変わる**（銘柄更新のたびに順位が入れ替わる）。

## 重要な注意

- **このストラテジーは発注を一切行わない。** 実発注に進む場合は、
  仮想売買ログで2〜4週間フォワード検証し、勝率・期待値が分析時の水準を
  維持しているかを確認したうえで、別途実装・レビューすること（CLAUDE.mdの方針）
- 検証サンプルは1週間分で、利益の大半が2026-07-17に集中している（地合い依存の可能性）
- 仮想決済の損切り/利確は現在値ベースの判定であり、実際の約定価格は
  板の厚さ・スリッページによりこれより不利になり得る
