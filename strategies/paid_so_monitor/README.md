# paid_so_monitor — 有償ストックオプション（業績条件付）×事前下落 モニタ

TDnet（適時開示）を毎日チェックし、**業績条件付きの有償ストックオプション**が
**発表前6ヶ月で一定以上下落していた**銘柄に新規発行されたら通知する。

検知・通知のみで**発注は行わない**。kabuランナーとは独立した1日1回実行のバッチツール。
実弾はもちろん、仮想売買にも進めていない段階の**監視ツール**。

## なぜこれが効くかもしれないのか

有償ストックオプションは行使価格を払う必要があり、**業績条件付き**（目標未達なら
権利行使できない設計）は経営陣・従業員が自ら「未達なら損をする」賭けに出ていることになる。
これを株価が下がった局面であえて出すのは、経営陣が「業績目標を達成できる」と
自ら表明しているに近い、という読み。

### 検証結果（2018-2026年・TDnet開示89件をYahoo Finance日足で検証）

詳細: [`../../analysis/output/2026-09-05/new_signal_paid_so_2026-09-05.md`](../../analysis/output/2026-09-05/new_signal_paid_so_2026-09-05.md)

| 区分（発表後6ヶ月リターン） | 件数 | 勝率 | 平均 | 中央値 |
|---|---:|---:|---:|---:|
| 業績条件あり・6ヶ月で20%以上下落 | 13 | 69.2% | +26.2% | +14.3% |
| 業績条件あり・6ヶ月で30%以上下落 | 8 | 75.0% | +27.7% | +14.2% |
| 業績条件なし（下落フィルタ問わず） | 33 | 33.3% | -11.2% | -11.8% |
| （比較）発表前6ヶ月で上昇していた銘柄 | 35 | 45.7% | -5.8% | — |

**まだ弱い点（率直に）**:
- 最良の区分でもn=8〜13で、二項検定は有意水準に届かない（p=0.27〜0.29）
- 個別銘柄の振れ幅が大きい（-80.7%〜+188.7%）。集中リスクが高い
- 下落40%以上のバケットだけ成績が崩れる（しきい値がなめらかに単調改善していない）

**この段階では通知して終わり。** 買うかどうかは必ず人が判断する。

## セットアップ

TDnet非公式ミラーAPI（`webapi.yanoshin.jp`）・Yahoo Financeともに**APIキー不要**。

```powershell
cd strategies\paid_so_monitor
pip install -r requirements.txt
cd src
python main.py --config ../config.yaml
```

1日1回の実行を想定（開示自体が不定期だが、取りこぼし防止のため日次を推奨）。
状態は `state/seen.json` に永続化され、同じ開示は二度評価しない。
ログは `logs/paid_so_monitor_YYYY-MM-DD.log` に日付別で保存。

**初回は遡ってチェックする**とよい（既定は30日）:

```powershell
python main.py --config ../config.yaml --days 400
```

## 処理の流れ

1. TDnet非公式ミラーAPIで、前回チェック日〜本日の開示から
   「有償ストックオプションの発行に関するお知らせ」（初回付与の公告。
   内容確定・訂正・消滅・行使・消却・放棄の後追い開示は除外）を抽出
2. タイトルに「業績」を含むもの（業績条件付き）だけを候補にする
   （`screen.require_performance_condition: false` で無効化可能）
3. 発表前6ヶ月（既定182日）の株価下落率をYahoo Finance日足から計算
4. `screen.min_decline_pct`（既定20%）以上下落していれば通知

## 設定（config.yaml）

- `tdnet.*`: 遡り日数・API呼び出しの分割日数・間隔
- `screen.require_keywords` / `require_title_contains` / `exclude_words`:
  TDnetタイトルのフィルタ条件
- `screen.performance_keyword` / `require_performance_condition`:
  「業績条件付き」の判定（タイトルの単純一致。検証で業績条件なしは
  一貫してマイナスだったため既定で必須にしている）
- `screen.decline_lookback_days` / `min_decline_pct`: 事前下落の判定条件

## 重要な前提・限界

- **TDnetの非公式ミラーAPIを使用している。** 公式のTDnet APIはJPX総研との契約が必要
  （月額24万円〜）で個人利用には現実的でないため、このミラーを使っている。
  取りこぼし・遅延の可能性はゼロではない
- **「業績条件付き」の判定はタイトルの単純キーワード一致。** 開示PDF本文の
  具体的な業績目標（売上/利益の何%成長か等）や行使価格・行使期間は読んでいない
- **証券コードはTDnetの5桁コードの末尾0を落として4桁ティッカーとして扱っている**
  （例: `94350`→`9435`＝光通信）
- **同一銘柄が複数回登場し得る**（光通信・メルコ・M-AppBank系などは複数年にわたり
  同種の発行を繰り返している）。独立した事象とは言い切れない
- 日足はYahoo Financeから取得している（`analysis/` と同じ方式）
- 私は投資助言の資格を持たない。通知は公開情報の集計結果であり、
  将来の成績を保証するものではない。売買の判断は利用者が行うこと
